5.Your responsibilities

Check what the scanner read

Text recognition is automated and it makes mistakes — misread totals, wrong dates, garbled merchant names. Extracted values are presented as an editable draft precisely because you are expected to check them. You are responsible for confirming every value before saving, and for the accuracy of any report you submit.

Back up your work

Browser storage is not permanent. Clearing site data, switching devices or browsers, or an operating-system cleanup can erase everything, and there is no server copy to restore from. Treat the app as a capture-and-export tool, not an archive: export each report when it is complete, and use the Backup card to keep an off-device copy. Data loss from browser storage being cleared or evicted is an expected limitation, not a defect.

Handle exported files under your own rules

Exported PDFs, CSVs, and backups contain real personal and financial information. Once you save or share one, it is yours to handle according to your organization's data-handling policies. The app has no visibility into, or control over, what happens to a file after it leaves the app.

Do not use development builds with real receipts

If you run the project yourself, note that in development mode (npm run dev) the Content-Security-Policy is not applied, so the browser-level restrictions on where the page may send network requests are inactive. Use synthetic receipts for local development; test with real files only against a production build (npm run build and npm run preview).
